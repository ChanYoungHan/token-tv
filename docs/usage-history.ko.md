# 주간 사용량의 일별 기록

웹 대시보드의 **주간 사용량 기록**에서 모든 계정의 사용량을 한 그래프로 비교합니다.
계정마다 고유한 색을 사용하며, 같은 색의 막대와 누적선은 같은 계정입니다.
일별 막대는 날짜별로 계정들을 나란히 표시합니다. 요약 수치와 상세 표에도 같은 색과 계정 이름을 표시합니다.
범례의 계정 이름을 누르면 해당 계정의 그래프를 숨기거나 다시 표시할 수 있습니다. 최소 한 계정은 표시합니다.
시계 이미지에는 이 그래프를 추가하지 않습니다.

## 무엇을 기록하나요?

- 첫 정상 주간 사용률을 시작 기준점으로 저장합니다. 이 값 자체를 오늘 사용량으로 더하지 않습니다.
- 이후 정상 조회 사이의 증가분을 기록합니다. 20%에서 28%가 되었다면 8%p입니다.
- 일별 막대는 그날 관측한 증가분의 합입니다. 누적선은 수집을 시작한 뒤 관측한 증가분의 합입니다.
- %p는 주간 한도의 퍼센트포인트이며 토큰 수나 호출 수가 아닙니다. 계정끼리 합산하지 않습니다.
- 주간 초기화가 확인되면 새 주기의 사용률부터 이어서 더합니다. 이전 주기의 보이지 않는 마지막 증가분을 추측하지 않습니다.
- 같은 주기의 사용률이 내려가면 이전 최고값을 유지합니다. 다시 올라온 값을 중복해서 더하지 않습니다.
- 한도나 초기화 정보가 예고 없이 바뀌면 새 기준점을 잡습니다.
- 기준 계정이 바뀌면 이메일 원문을 저장하지 않고 별도 식별자로 구분합니다.

처음 두 번의 정상 조회가 쌓이기 전에는 일별 사용량과 누적 요약이 `—`입니다.
두 번째 조회에서도 값이 같으면 그 구간의 관측 증가분은 0입니다.
기록을 시작하기 전 날짜의 데이터는 소급해서 만들지 않습니다.

## 날짜와 빠진 구간

한국 시간 `Asia/Seoul`(UTC+9)의 조회 날짜로 집계합니다.
자정에 걸친 짧은 조회 간격의 증가분은 다음 조회 날짜에 반영되므로 일별 값에는 조회 주기만큼의 경계 오차가 있습니다.
정상 조회만 기록하며 `OLD`, 로그인 실패, 알 수 없는 주간 값은 기록하지 않습니다.

긴 조회 중단(기본 15분 초과)이 날짜를 넘기면 그 사이 증가분을 어느 날짜에 배분할 수 없으므로 제외하고 새 관측값을 기준으로 이어갑니다.
같은 날짜 안에서 복구되면 증가분을 해당 날짜에 기록하고 부분 기록으로 표시합니다.
초기화, 수집 시작, 값 보정, 긴 중단이 있었던 날짜도 부분 기록입니다.
기록이 없는 날짜를 0으로 채우거나 누적선을 연결하지 않습니다.
따라서 표시되는 누적량은 실제 전체 사용량의 추정치가 아니라 **확인된 최소 증가분**입니다.

## 기간 조절

기본은 오늘을 포함한 최근 14일입니다.

- 그래프를 좌우로 드래그하면 같은 길이로 조회 기간을 이동합니다.
- 아래 선택기의 양 끝 손잡이를 드래그하면 기간을 늘리거나 줄입니다.
- 선택 영역 가운데를 드래그해 기간을 이동할 수도 있습니다.
- 확대·축소 버튼, 날짜 입력, 최근 2주 버튼을 사용할 수 있습니다.
- 손잡이에 키보드 초점을 두고 방향키로 하루, Page Up/Down으로 7일씩 조정할 수 있습니다.
- 일별 상세 수치는 **집계 기준과 일별 수치**를 펼쳐 확인합니다.

처음에는 최근 90일 범위를 탐색할 수 있고, 오래된 기록이 쌓이면 탐색 범위도 확장됩니다.
한 번에 최대 3,660일을 조회하며, DB의 과거 데이터는 자동 삭제하지 않습니다.

## 저장과 운영

Python 표준 라이브러리 SQLite를 사용합니다. 별도 DB 서버는 필요하지 않습니다.
DB 파일은 실행 상태 디렉터리의 `usage-history.sqlite3`이며 Docker에서는
`/data/token-tv/state/usage-history.sqlite3`입니다.
기존 `token-tv_token-tv-data` 볼륨에 저장하므로 컨테이너 교체 후에도 이어집니다.

`observations`에는 계정 식별자, 관측 시각, 주간 사용률, 초기화 시각, 증가분을 저장하고,
`daily_usage`에는 날짜별 집계를 저장합니다. OAuth 토큰, 로그인 코드, 이메일 원문은 저장하지 않습니다.
동일 관측 시각은 한 번만 처리하며 재시작 후에도 마지막 관측 기준점을 이어갑니다.
SQLite WAL을 사용하므로 실행 중인 DB를 파일 하나만 복사하는 방식으로 백업하지 않습니다.
SQLite 백업 기능을 사용하거나 서비스를 멈추고 DB 관련 파일을 함께 보관합니다.

`GET /history`는 기본 14일 기록과 설정된 계정 목록을 반환합니다.
`account`, `start`, `end` 쿼리로 계정과 날짜를 지정할 수 있습니다.
예: `/history?account=claude_a&start=2026-10-04&end=2026-10-17`.
미래 날짜, 역순 날짜, 3,660일을 넘는 요청은 거부합니다.
DB 쓰기에 문제가 생겨도 기존 사용량 조회와 시계 전송은 계속 진행합니다.

## 시간별 집계

**시간별**을 누르면 한국 시간의 매시 정각부터 다음 정각 전까지 관측한 증가분을 묶습니다.
예를 들어 08:00 이상 09:00 미만의 정상 조회는 08시 막대에 들어갑니다.
기본은 현재 시간을 포함한 최근 24시간입니다. **일별**로 돌아가면 기본 최근 2주를 보여줍니다.
시간별 보기에서도 전체 계정 색상, 범례, 누적선, 드래그와 확대·축소를 사용합니다.
날짜 입력은 날짜·시간 입력으로 바뀌며 최소 한 시간부터 선택할 수 있습니다.

기존 `observations`의 시각과 증가분을 집계하므로, 기능 추가 이전에 이 DB에 저장된 관측도 바로 시간별로 볼 수 있습니다.
별도 DB 이관이나 데이터 초기화가 없으며, 시간별·일별의 수집 누적 기준은 같습니다.
누적선은 조회 기간 시작 시점에 0으로 초기화하지 않습니다.
기록이 없는 시간은 `—`이며 현재 시간은 아직 수집 중입니다.

사용량 조회 주기는 약 5분으로 유지합니다. 증가분은 다음 관측 시각에 반영되므로 정시 경계에는 조회 주기만큼의 오차가 있습니다.
긴 중단이 같은 날짜 안에서 복구되면 증가분이 복구된 시간대에 모여 보일 수 있으며 부분 기록으로 표시합니다.
날짜를 넘긴 긴 중단 때문에 원래 일별 기록에서 제외된 증가분은 시간별 보기에서도 복원하지 않습니다.

시간별 API는 `GET /history?granularity=hour`입니다. `account`, `start`, `end`를 함께 사용할 수 있습니다.
날짜·시간은 한국 시간으로 해석하며 정각을 지정합니다. 예: `start=2026-10-17T00:00&end=2026-10-17T08:00`.
끝 시간은 포함하고, 한 번에 최대 2,160시간(90일)을 조회할 수 있습니다. 미래 시간은 거부합니다.
시간별 그래프의 탐색기는 기본 최근 7일을 제공하고, 기록이 쌓이면 최대 90일까지 확장됩니다.
일별 API의 기존 기본 동작은 유지합니다.

## 주간 한도 리셋 포인트

일별·시간별 그래프에 계정 색상의 **◆ 마커와 세로 점선**으로 리셋을 인식한 지점을 표시합니다.
마커는 해당 시각의 수집 누적량(오른쪽 축)에 위치합니다. 누적량은 리셋 후에도 이어집니다.
마우스를 올리거나 누르면 계정, 인식 시각(한국 시간, 초 단위), 새 주기의 사용률과 누적량을 볼 수 있습니다.
키보드 Tab으로 마커에 초점을 두어도 표시하며 Escape로 설명을 닫습니다.
기간 이동·확대·축소와 계정 숨김에 맞춰 마커도 갱신하고, 아래에 선택 기간의 리셋 인식 횟수를 표시합니다.

표시 시각은 정상 조회에서 **리셋을 확인한 시각**입니다. 실제 서버 초기화 시각과는 조회 간격만큼 차이 날 수 있습니다.
기존 초기화 예정 시각이 지났고 다음 초기화 예정 시각이 새 주기로 이동한 정상 관측만 표시합니다.
로그인 갱신, 사용률 하락이나 초기화 정보 보정만으로는 마커를 만들지 않습니다.
아직 확인된 리셋이 없으면 마커 없이 `리셋 인식 0회`를 표시합니다.

기존 DB의 `observations.reset=1` 기록도 바로 표시하며 별도 데이터 이관은 없습니다.
일별·시간별 API의 `reset_events`에는 `observed_at`, `used_percent`, `next_reset_at`, `cumulative_pp`를 반환합니다.
